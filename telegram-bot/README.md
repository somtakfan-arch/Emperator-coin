# Bad Casino — Telegram Bot

Развлекательный казино-бот для Telegram на **Python + aiogram 3**. Валюта —
виртуальные фишки (1 фишка = 1 Telegram Star при покупке), **без вывода
и обмена обратно на деньги**. Это принципиальное архитектурное решение: как
только выигрыш можно обналичить, сервис становится реальным азартным бизнесом
и требует лицензии на игорную деятельность почти в любой юрисдикции. Модель
здесь — «social casino» (как Slotomania и подобные): платный вход, бесплатный
ежедневный бонус, никакого кэшаута.

Все выплаты собраны в секции «Payouts» в `config.py` — там же их и менять.
**Подписи на кнопках формируются прямо из этих констант**, а условия выигрыша
описаны в тексте каждой игры, поэтому игрок всегда видит настоящие шансы.
Если правите множители — не подменяйте цифры только в UI: люди платят за фишки
реальными звёздами, и расхождение между показанным и фактическим шансом
превращает «сложность» в обман.

Стартового баланса нет (`STARTING_BALANCE = 0`): новый игрок начинает с нуля,
и единственный бесплатный вход — ежедневный бонус (200 фишек).

Кости и слоты используют **нативную анимацию Telegram** (`send_dice`) — результат
генерируется на серверах Telegram, а не ботом, что выглядит честнее в глазах
игроков (это не крипто-provably-fair, но исключает подозрения в накрутке на
уровне бота).

## Админ-панель

Команда `/admin` (и кнопка «🛠 Админка» в главном меню) доступна только тем,
чей Telegram ID есть в `ADMIN_IDS`. Владелец бота прописан в `config.py`,
остальных можно добавить переменной окружения `ADMIN_IDS=111,222`.

- **💸 Выдать фишки** — `<ID или @username> <количество>`, отрицательное
  число списывает. По числовому ID можно начислить даже тому, кто ещё не
  запускал бота: строка игрока создастся, и фишки будут ждать его на `/start`.
  Игрок получает уведомление о начислении.
- **🔍 Найти игрока** — карточка по ID или @username.
- **📊 Статистика** — игроки, фишки на руках, обороты, пополнения в звёздах.

Доступ закрыт фильтром **на уровне роутера**, а не на отдельных обработчиках,
поэтому забытый декоратор не может открыть панель постороннему.

Выданные админом фишки пишутся в таблицу `admin_grants` отдельно от `topups`:
первые созданы из воздуха, вторые обеспечены реальными звёздами, и смешивать
их в отчётности не стоит.

## Установка

```bash
cd telegram-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

1. Получите токен бота у [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Впишите его в `.env` как `BOT_TOKEN`.
3. Оплата звёздами (Stars) включена по умолчанию у всех ботов — отдельный
   `provider_token` не нужен, платежи идут через `currency="XTR"`. Пополнить
   можно готовым пакетом или своей суммой (кнопка «✏️ Своя сумма», от 1 до
   100 000 звёзд — потолок одного инвойса в Telegram).
4. Запуск:

```bash
python bot.py
```

База данных — SQLite (`casino.db`), создаётся автоматически при первом запуске.

## Деплой на Railway

В репозитории уже есть `Procfile`, `railway.json` и `.python-version` —
Railway распознает проект как Python-воркер автоматически (Nixpacks).

1. На [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**
   → выбрать этот репозиторий.
2. В настройках сервиса (**Settings → Root Directory**) указать `telegram-bot`
   — иначе Railway попытается собрать весь репозиторий (там есть отдельный
   PWA-проект в корне).
3. **Variables** → добавить `BOT_TOKEN` (значение — токен из @BotFather).
   **Никогда не коммитьте токен в код** — только через переменные окружения
   хостинга.
4. Чтобы балансы игроков не терялись при передеплое: **Settings → Volumes**
   → создать том, примонтировать в `/data`, и добавить переменную
   `DB_PATH=/data/casino.db` (по умолчанию SQLite-файл лежит рядом с кодом
   на эфемерном диске и сбрасывается при каждом редеплое).
5. Deploy. Логи — во вкладке **Deployments**; бот использует long-polling,
   отдельный веб-порт открывать не нужно.

## Важные ограничения и дальнейшие шаги для продакшена

- **Юридический дисклеймер и возраст 18+** уже есть в `/start`, но перед
  реальным запуском проконсультируйтесь с юристом по законам вашей и целевых
  юрисдикций (Stars-платежи и «игровые» механики регулируются по-разному).
  Не превращайте фишки в выводимые средства без лицензии.
- Хранилище FSM — `MemoryStorage` (в памяти процесса): состояние партии в
  блэкджек теряется при перезапуске бота. Для продакшена с несколькими
  инстансами используйте `RedisStorage`.
- Нет анти-фрод/лимитов на частоту ставок и минимального возраста игрока —
  добавьте проверку при необходимости (например, подтверждение 18+ в `/start`).
- `ADMIN_IDS` в `.env` зарезервирован для будущих админ-команд (статистика,
  бан, ручная выдача фишек) — сейчас не используется в коде.
