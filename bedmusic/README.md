# 🎧 Bed Music

SoundCloud-подобный музыкальный бот для Telegram: музыканты заводят профиль и
выкладывают треки, слушатели листают ленту, ищут и лайкают.

Бот: [@Bed_Musicbot](https://t.me/Bed_Musicbot)

## Что умеет

| Экран | Что происходит |
| --- | --- |
| `/start` | Карточка с информацией о боте и **красная** кнопка «Зарегистрироваться» |
| Регистрация | Три шага по очереди: **имя музыканта** → **описание** → **аватарка** |
| `/upload` | Загрузка трека (аудио, документ-аудио или голосовое) + название |
| `/feed` | Лента свежих релизов с постраничной навигацией |
| `/search` | Поиск по названию трека и по имени артиста (регистронезависимый, включая кириллицу) |
| `/profile` | Профиль с аватаркой, описанием и статистикой; редактирование любого поля |
| ❤️ | Лайки и личная подборка «Мне нравится» |

Описание и аватарку на регистрации можно пропустить — они добавляются позже
через «Редактировать профиль».

## Цветные кнопки

Цвет задаётся полем `style` у `InlineKeyboardButton`, добавленным в
[Bot API 9.4](https://core.telegram.org/bots/api-changelog) (9 февраля 2026):

| Значение | Цвет | Где используется |
| --- | --- | --- |
| `danger` | 🔴 красный | «Зарегистрироваться», отмена, удаление |
| `success` | 🟢 зелёный | «Загрузить трек», «Слушать», подтверждения |
| `primary` | 🔵 синий | навигация, лента, поиск |

Поле опциональное: клиенты, которые ещё не умеют его читать, просто рисуют
кнопку в стандартном стиле, так что бот работает везде.

Требует `aiogram >= 3.30` — в более ранних версиях поля `style` в модели нет.

## Локальный запуск

```bash
cd bedmusic
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # и вписать свой BOT_TOKEN
export $(grep -v '^#' .env | xargs)

python -m bot.main
```

Проверка всех сценариев на мок-транспорте, без обращения к Telegram:

```bash
python -m tests.e2e_check
```

## Деплой на Railway

Бот уже задеплоен: проект **bed-music**, сервис **bed-music-bot**.

Сборку ведёт Railpack — он сам определяет Python по `requirements.txt` и берёт
команду запуска из `Procfile`. Отдельный конфиг сборки не нужен: Config as Code
(`railway.json` / `railway.toml`) объявлен устаревшим и перестанет работать
1 декабря 2026, поэтому в репозитории его нет.

### Выкатить новую версию

```bash
cd bedmusic
railway up --service bed-music-bot
```

Загружается содержимое каталога `bedmusic/`, поэтому **Root Directory сервиса
должен быть `/`**, а не `bedmusic` — иначе Railway будет искать `bedmusic/bedmusic`
и сборка упадёт на `railpack prepare exited with an error`.

### Настройки сервиса

| Что | Значение | Зачем |
| --- | --- | --- |
| Root Directory | `/` | загружается уже каталог `bedmusic` |
| Volume | `/data` | иначе база стирается при каждом редеплое |
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) | |
| `DB_PATH` | `/data/bedmusic.db` | база на вольюме |
| Replicas | `1` | long polling: два процесса на одном токене будут отбирать друг у друга апдейты |
| Restart policy | `ON_FAILURE`, до 10 попыток | |

HTTP-порт боту не нужен, публичный домен генерировать не надо.

Признак живого деплоя в логах:

```
bedmusic: database ready at /data/bedmusic.db
bedmusic: starting @Bed_Musicbot (Bed Music)
aiogram.dispatcher: Run polling for bot @Bed_Musicbot
```

### Автодеплой по git push

Сейчас **не настроен**: GitHub-приложение не подключено к аккаунту Railway,
поэтому у сервиса нет repo-триггера и деплой идёт загрузкой через `railway up`.

Чтобы включить: в дашборде Railway подключить GitHub, затем в сервисе выбрать
репозиторий и ветку. При этом Root Directory нужно поменять с `/` на `bedmusic`
— при деплое из репозитория корнем становится корень репозитория, а не каталог
бота.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `BOT_TOKEN` | да | — | Токен от @BotFather |
| `DB_PATH` | нет | `data/bedmusic.db` | Путь к файлу SQLite |
| `PAGE_SIZE` | нет | `5` | Треков на страницу ленты |

## Как устроено

```
bedmusic/
├── bot/
│   ├── main.py            точка входа, polling
│   ├── config.py          конфиг из переменных окружения
│   ├── db.py              SQLite-схема и запросы
│   ├── keyboards.py       клавиатуры, в т.ч. цветные кнопки
│   ├── texts.py           все тексты в одном месте
│   └── handlers/
│       ├── start.py       /start, /menu, /help
│       ├── registration.py  FSM: имя → описание → аватарка
│       ├── profile.py     профиль и редактирование
│       ├── upload.py      FSM загрузки трека
│       ├── browse.py      лента, поиск, лайки, воспроизведение
│       └── fallback.py    необработанный ввод и устаревшие кнопки
└── tests/e2e_check.py     прогон всех сценариев на мок-транспорте
```

Аудио и аватарки **не хранятся** на сервере: в базе лежат только Telegram
`file_id`, а сами файлы остаются на серверах Telegram. Поэтому база крошечная,
а объектное хранилище не нужно.
