# 🎧 Bed Music

SoundCloud-подобный музыкальный бот для Telegram: музыканты заводят профиль и
выкладывают треки, слушатели листают ленту, ищут и лайкают.

Бот: [@Bed_Musicbot](https://t.me/Bed_Musicbot)

## Что умеет

| Экран | Что происходит |
| --- | --- |
| `/start` | Карточка с информацией о боте и **красная** кнопка «Зарегистрироваться» |
| Регистрация | Три шага по очереди: **имя музыканта** → **описание** → **аватарка** |
| `/upload` | Загрузка трека (аудио, документ-аудио или голосовое) + название |
| `/feed` | Лента свежих релизов с постраничной навигацией |
| `/search` | Поиск по названию трека и по имени артиста (регистронезависимый, включая кириллицу) |
| `/profile` | Профиль с аватаркой, описанием и статистикой; редактирование любого поля |
| ❤️ | Лайки и личная подборка «Мне нравится» |
| `/wallet` | Баланс в BED / TON / USDT и история операций |
| `/deals` | Сделки по продаже битов |

Описание и аватарку на регистрации можно пропустить — они добавляются позже
через «Редактировать профиль».

## Продажа битов

Продавец выставляет цену на свой бит в BED, TON или USDT. У остальных на
карточке трека появляется кнопка покупки, и дальше сделка идёт по шагам:

1. **Запрос.** Покупатель нажимает «Купить». Сумма сразу списывается с его
   баланса и удерживается сервисом — сделка обеспечена с первой секунды.
2. **Согласие продавца.** Он принимает или отклоняет; при отказе деньги
   возвращаются автоматически.
3. **Анкета продавца.** Он отвечает на вопросы договора по одному сообщению.
   Каждый ответ проверяется: ФИО, даты, паспорт, телефон, e-mail, BPM. Раздел
   о согласии законного представителя появляется, только если Автору нет 18.
4. **Файлы бита.** Продавец отдаёт сервису WAV, MP3, stems и проектный файл.
   Без хотя бы одного файла дальше не пройти.
5. **Анкета покупателя.** Ему сразу сообщают, сколько файлов уже в залоге.
6. **Черновик.** Обе стороны получают `.docx`, заполненный с двух сторон.
7. **Подтверждение.** Кнопку «Подтвердить» должны нажать оба.
8. **Подписи.** Каждый присылает фото своей подписи.
9. **Готово.** Покупатель получает файлы бита и подписанный договор, продавец —
   деньги, бит помечается проданным.

Обе стороны сделки в залоге, а не только деньги: файлы уходят покупателю
**до** выплаты продавцу. Если передача сорвалась, сделка не закрывается, деньги
остаются удержаны, и обе стороны получают кнопку «Повторить передачу».

Файлы хранятся как Telegram `file_id` — байты остаются на серверах Telegram,
поэтому размер ограничен только самим Telegram, а не ботом. У отменённой сделки
файлы удаляются.

Отменить сделку можно на любом шаге до завершения — удержанная сумма
возвращается покупателю.

### Договор

Текст следует шаблону «Договор об отчуждении исключительного права на
музыкальное произведение (инструментальную композицию)» вместе с Приложением
№ 1 (акт приёма-передачи). Единственное намеренное отступление — раздел 3: в
шаблоне расчёты в рублях переводом или наличными, здесь они описывают
криптовалюту и эскроу.

Незаполненные поля остаются подчёркиваниями, а не ломают генерацию, — документ
всегда можно дописать от руки.

### Персональные данные

Анкета собирает паспортные данные обеих сторон. После закрытия сделки —
успешного или отменённого — ответы **удаляются из базы** (`purge_deal_fields`);
остаётся только запись о самой сделке. Готовый договор остаётся у сторон на
руках, поэтому хранить исходные ответы незачем, а риск утечки паспортов —
вполне реальный.

### Деньги

Внутренние балансы ведутся в минимальных единицах целыми числами: BED и TON —
9 знаков, USDT — 6. Списание идёт условием прямо в `UPDATE`, поэтому баланс не
может уйти в минус даже при гонке. Каждое движение пишется в `ledger`, а
переходы эскроу защищены состоянием сделки — двойное нажатие не заплатит дважды.

> **Пополнение и вывод в сеть пока не подключены.** Для этого нужен
> кошелёк-казна сервиса: задай `TON_TREASURY_MNEMONIC` в переменных Railway.
> Пока его нет, эскроу полностью работает на внутренних балансах, а пополняет
> их админ командой `/credit <user_id> <сумма> <BED|TON|USDT>`
> (список админов — в `ADMIN_IDS`). `/audit` показывает, сколько сейчас
> удерживается в эскроу.


## Цветные кнопки

Цвет задаётся полем `style` у `InlineKeyboardButton`, добавленным в
[Bot API 9.4](https://core.telegram.org/bots/api-changelog) (9 февраля 2026):

| Значение | Цвет | Где используется |
| --- | --- | --- |
| `danger` | 🔴 красный | «Зарегистрироваться», отмена, удаление |
| `success` | 🟢 зелёный | «Загрузить трек», «Слушать», подтверждения |
| `primary` | 🔵 синий | навигация, лента, поиск |

Поле опциональное: клиенты, которые ещё не умеют его читать, просто рисуют
кнопку в стандартном стиле, так что бот работает везде.

Требует `aiogram >= 3.30` — в более ранних версиях поля `style` в модели нет.

## Локальный запуск

```bash
cd bedmusic
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # и вписать свой BOT_TOKEN
export $(grep -v '^#' .env | xargs)

python -m bot.main
```

Проверка всех сценариев на мок-транспорте, без обращения к Telegram:

```bash
python -m tests.e2e_check    # регистрация, загрузка, лента, поиск, лайки
python -m tests.deal_check   # продажа бита от запроса до подписанного договора
```

## Деплой на Railway

Бот уже задеплоен: проект **bed-music**, сервис **bed-music-bot**.

Сборку ведёт Railpack — он сам определяет Python по `requirements.txt` и берёт
команду запуска из `Procfile`. Отдельный конфиг сборки не нужен: Config as Code
(`railway.json` / `railway.toml`) объявлен устаревшим и перестанет работать
1 декабря 2026, поэтому в репозитории его нет.

### Выкатить новую версию

```bash
cd bedmusic
railway up --service bed-music-bot
```

Загружается содержимое каталога `bedmusic/`, поэтому **Root Directory сервиса
должен быть `/`**, а не `bedmusic` — иначе Railway будет искать `bedmusic/bedmusic`
и сборка упадёт на `railpack prepare exited with an error`.

### Настройки сервиса

| Что | Значение | Зачем |
| --- | --- | --- |
| Root Directory | `/` | загружается уже каталог `bedmusic` |
| Volume | `/data` | иначе база стирается при каждом редеплое |
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) | |
| `DB_PATH` | `/data/bedmusic.db` | база на вольюме |
| Replicas | `1` | long polling: два процесса на одном токене будут отбирать друг у друга апдейты |
| Restart policy | `ON_FAILURE`, до 10 попыток | |

HTTP-порт боту не нужен, публичный домен генерировать не надо.

Признак живого деплоя в логах:

```
bedmusic: database ready at /data/bedmusic.db
bedmusic: starting @Bed_Musicbot (Bed Music)
aiogram.dispatcher: Run polling for bot @Bed_Musicbot
```

### Автодеплой по git push

Сейчас **не настроен**: GitHub-приложение не подключено к аккаунту Railway,
поэтому у сервиса нет repo-триггера и деплой идёт загрузкой через `railway up`.

Чтобы включить: в дашборде Railway подключить GitHub, затем в сервисе выбрать
репозиторий и ветку. При этом Root Directory нужно поменять с `/` на `bedmusic`
— при деплое из репозитория корнем становится корень репозитория, а не каталог
бота.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `BOT_TOKEN` | да | — | Токен от @BotFather |
| `DB_PATH` | нет | `data/bedmusic.db` | Путь к файлу SQLite |
| `PAGE_SIZE` | нет | `5` | Треков на страницу ленты |
| `ADMIN_IDS` | нет | пусто | Кому доступны `/credit` и `/audit` |
| `TON_TREASURY_MNEMONIC` | нет | пусто | Мнемоника казны. Пока пусто — пополнение и вывод в сеть выключены |

## Как устроено

```
bedmusic/
├── bot/
│   ├── main.py            точка входа, polling
│   ├── config.py          конфиг из переменных окружения
│   ├── db.py              SQLite-схема и запросы
│   ├── keyboards.py       клавиатуры, в т.ч. цветные кнопки
│   ├── texts.py           все тексты в одном месте
│   └── handlers/
│       ├── start.py       /start, /menu, /help
│       ├── registration.py  FSM: имя → описание → аватарка
│       ├── profile.py     профиль и редактирование
│       ├── upload.py      FSM загрузки трека
│       ├── browse.py      лента, поиск, лайки, воспроизведение
│       ├── sell.py        выставление бита на продажу
│       ├── deal.py        сделка: анкета, договор, подписи, расчёт
│       ├── wallet.py      балансы, история, админские /credit и /audit
│       └── fallback.py    необработанный ввод и устаревшие кнопки
├── money.py               валюты и суммы в минимальных единицах
├── questions.py           анкета договора (декларативно)
├── contract.py            генерация .docx договора и акта
├── escrow.py              удержание, выплата и возврат средств
└── tests/
    ├── e2e_check.py       базовые сценарии
    └── deal_check.py      полная сделка между двумя пользователями
```

Аудио и аватарки **не хранятся** на сервере: в базе лежат только Telegram
`file_id`, а сами файлы остаются на серверах Telegram. Поэтому база крошечная,
а объектное хранилище не нужно.
