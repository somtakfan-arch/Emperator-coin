# Бамп версии service worker

## Зачем

Оба service worker'а в репозитории работают по схеме stale-while-revalidate:
`caches.match(req)` отдаётся пользователю **до** сетевого запроса. Старая
версия файла показывается как минимум один заход, а на офлайн-устройстве —
неограниченно долго.

Кэш чистится только в обработчике `activate`, и только для ключей, не равных
текущему `CACHE_VERSION`. Значит: пока строка версии не изменилась, старый
кэш считается актуальным и никогда не удаляется.

Вывод: изменение ассета без бампа версии не доезжает до пользователей.

## Какой файл править

| Что изменил | Какой sw.js бампать | Текущая версия |
|---|---|---|
| `index.html`, `styles.css`, `landing.js`, `manifest.json`, `icons/*`, `app/**` | `sw.js` (корень) | `remindly-v1` |
| `stickman/**` (кроме самого `stickman/sw.js`) | `stickman/sw.js` | `stickanim-v1` |
| `games/**` | ничего — у games нет service worker'а | — |

## Процедура

1. Определи, какие файлы из диффа входят в `PRECACHE_URLS` нужного `sw.js`.
   Если ни один — бамп не нужен, остановись.

2. Подними числовой суффикс на единицу. Формат — `<имя>-v<N>`:

   ```
   sed -i 's/remindly-v1/remindly-v2/' sw.js
   sed -i 's/stickanim-v1/stickanim-v2/' stickman/sw.js
   ```

   Не выдумывай новую схему версий (даты, хэши, семвер) — она сломает
   `grep`-проверки и привычный вид диффа.

3. Если добавил или удалил файл, который должен кэшироваться, синхронно
   поправь массив `PRECACHE_URLS`. Пути в нём — относительные, со `./`.
   Ошибка здесь фатальна: `cache.addAll()` отклоняет **весь** промис, если
   хоть один URL отдаёт не-200, и service worker вообще не установится.

4. Проверь:

   ```
   python3 .claude/skills/check/check.py
   ```

## Частые ошибки

- Бампнули корневой `sw.js`, а правили `stickman/` — версия не та, эффекта нет.
- Добавили файл в `PRECACHE_URLS` с опечаткой в пути — SW молча не ставится
  у всех пользователей сразу. Всегда прогоняй `check.py`.
- Правка только `games/**` — бампать нечего, у этой папки нет ни SW, ни манифеста.
