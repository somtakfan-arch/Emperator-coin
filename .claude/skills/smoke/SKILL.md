# Дымовой прогон в браузере

`check` ловит статические ошибки — синтаксис, битые пути, версию кэша. Он не
запускает код. Этот скилл дополняет его: поднимает статический сервер,
открывает каждое приложение в headless Chromium, ждёт `networkidle` и
проверяет отсутствие исключений, ошибок консоли и ответов ≥ 400.

```
python3 .claude/skills/smoke/smoke.py
python3 .claude/skills/smoke/smoke.py --shots    # + скриншоты в /tmp/smoke/
```

Код возврата 1, если хоть одна страница проблемная. Порт выбирается
свободный автоматически — параллельные запуски друг другу не мешают.

Проверяются все четыре точки входа: `/`, `/app/`, `/stickman/`,
`/games/2-4-player-games/`. Добавил новое приложение — допиши его в список
`PAGES` в `smoke.py`.

## Что нужно один раз в сессии

```
pip install playwright
```

Браузер уже есть в образе, **`playwright install` запускать не надо** — она
полезет качать другую сборку и сломает то, что работает.

## Особенности окружения (зашиты в скрипт, не трогать)

- `executable_path="/opt/pw-browsers/chromium"` — версия браузера в образе не
  совпадает с той, которую ждёт свежий пакет playwright, поэтому путь задан
  явно.
- `--no-sandbox` — сессия работает под root, без этого флага рендерер молча
  падает и любая страница отдаёт `ERR_EMPTY_RESPONSE`. Это самая
  дезориентирующая ошибка здесь: выглядит как мёртвый сервер, хотя `curl`
  на тот же URL отвечает 200.
- `--no-proxy-server` — в окружении настроен исходящий HTTPS-прокси, через
  который localhost ходить не должен.

## Более сложные сценарии

Для интерактивных проверок (клики, ввод, состояние после действий) есть
вендоренный официальный скилл `webapp-testing` — там паттерн
«разведка → действие», хелпер управления серверами и примеры. Флаги запуска
браузера бери отсюда, они специфичны для этого образа.

## Чего скрипт не проверяет

Геймплей, вёрстку на глаз, работу офлайн-режима после установки PWA. Для
визуальной проверки гоняй с `--shots` и смотри картинки.
