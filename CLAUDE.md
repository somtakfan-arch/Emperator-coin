# Emperator-coin

Монорепозиторий из трёх независимых статических веб-приложений без сборки,
без npm и без зависимостей. Всё, что лежит в git, — это и есть продакшн:
файлы отдаются GitHub Pages как есть.

## Структура

| Путь | Что это | Точка входа |
|---|---|---|
| `index.html`, `styles.css`, `landing.js` | Лендинг Remindly | `/` |
| `app/` | PWA «Remindly» — напоминания, стрики, папки, заметки, календарь (`app.js`, ~2500 строк) | `/app/` |
| `stickman/` | PWA «StickAnim» — покадровый аниматор стикмена на суставах (`app.js`, ~820 строк) | `/stickman/` |
| `games/2-4-player-games/` | «2 3 4 Player Games» — 12 мини-игр в **одном** файле `index.html` (~4000 строк) | `/games/2-4-player-games/` |
| `icons/` | Иконки Remindly (генерируются, не рисуются руками) | — |
| `scripts/` | Python-генераторы иконок (нужен Pillow) | — |

Три приложения не связаны кодом. Правка в одном не задевает другие.

## Ключевые соглашения

**Никакой сборки.** Нет package.json, нет бандлера, нет транспиляции. Пиши
обычный ES2020+, который браузер исполняет напрямую. Не добавляй зависимости
и не предлагай перевести проект на фреймворк без явной просьбы.

**Язык интерфейса — русский.** Все строки UI, комментарии в коде мини-игр и
описания — на русском. Держи этот стиль.

**Три отдельных service worker'а с версионированным кэшем:**

- `sw.js` — `CACHE_VERSION = "remindly-v1"`, кэширует лендинг + `app/`
- `stickman/sw.js` — `CACHE_VERSION = "stickanim-v1"`
- у `games/` service worker'а нет вообще

Стратегия — stale-while-revalidate: пользователь сначала получает кэш.
**Любая правка ассета обязана сопровождаться бампом `CACHE_VERSION`** в
соответствующем `sw.js`, иначе у установивших PWA залипнет старая версия.
См. скилл `bump-sw`.

**Состояние живёт в localStorage:**

- Remindly → ключ `remindly_state_v1` (`app/app.js:4`)
- StickAnim → `STORAGE_KEY` + `ACTIVE_KEY` (`stickman/app.js:80`)

Меняешь форму сохранённых данных — либо мигрируй старое состояние, либо
подними суффикс `_v2` у ключа. Молча ломать данные пользователей нельзя.

**Мини-игры.** Все 12 живут в одном `games/2-4-player-games/index.html`,
разбитом на 14 пронумерованных секций (`grep -n '^ \* [0-9]*\.'`). Вся
балансировка — в объекте `CONFIG` (секция 1). Игры наследуют `BaseGame`
(секция 9) и регистрируются в `GAME_LIST` (~строка 766). См. скилл
`new-minigame`.

**Иконки не редактируются вручную** — они генерируются
`scripts/gen_icons.py` и `scripts/gen_stickman_icons.py`. См. скилл `icons`.

## Проверка перед пушем

```
python3 .claude/skills/check/check.py
```

Скрипт проверяет валидность манифестов, существование всех файлов из
`PRECACHE_URLS`, синтаксис JS через `node --check` и то, что `CACHE_VERSION`
поднят, если изменились закэшированные ассеты. Гоняй его перед каждым
коммитом — CI этого не делает.

## Дымовой прогон в браузере

```
pip install playwright                      # один раз в сессии
python3 .claude/skills/smoke/smoke.py       # + --shots для скриншотов
```

Открывает все четыре приложения в headless Chromium и ловит то, что
статическая проверка не видит: исключения JS, ошибки консоли, 404.
`playwright install` запускать не надо — браузер уже в образе. Подробности и
обязательные флаги запуска — в скилле `smoke`.

## Деплой

`.github/workflows/deploy-pages.yml` собирает `_site` из явного списка путей
и публикует на GitHub Pages. Два следствия:

1. Воркфлоу срабатывает только на веток из списка `on.push.branches`. Список
   содержит устаревшие ветки `claude/*`; чтобы задеплоить с новой ветки, её
   нужно туда добавить.
2. Шаг `Prepare site directory` копирует пути **поимённо**. Добавил папку
   верхнего уровня — добавь её в `cp -r`, иначе она не попадёт на Pages.

## Локальный запуск

```
python3 -m http.server 8000
```

Открывать через `http://localhost:8000`, а не `file://` — service worker и
манифест по `file://` не работают.
