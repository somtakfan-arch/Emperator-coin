# Bed Dialog Bot

Телеграм-бот в духе NeverDialogBot: подключается к вашему личному аккаунту через
официальную функцию Telegram **"Автоматизация чатов" (Business Bots)** и в личных
сообщениях с ботом присылает:

- 🗑 удалённые собеседником сообщения (текст);
- ✏️ изменённые сообщения (старый и новый текст);
- 🗑 удалённые фото (с самим фото);
- 🔥 одноразовые ("исчезающие") фото — если на них ответили в чате, пока бот работал.

Работает только для личных (1-на-1) чатов — это ограничение самой функции
Telegram Business, не бота.

## Команды

Команды пишутся владельцем аккаунта прямо в чат с человеком, на которого они
должны подействовать (текст самой команды в чате скрывается — бот
перезаписывает его через `editMessageText`, других способов спрятать
сообщение Bot API не даёт):

- `.ban <минуты>` — "банит" собеседника на N минут. Telegram не позволяет
  ботам по-настоящему блокировать контакт или удалять чужие сообщения, поэтому
  на деле бот просто автоматически отвечает собеседнику на каждое его
  сообщение, пока бан активен.
- `.unban` — снять бан раньше времени.
- `.spam <количество> <сообщение>` — отправить сообщение N раз подряд
  (максимум 100 сообщений, 500 с премиумом; укладывается в 45 секунд).
- `.help` — список команд приходит вам в личку с ботом.

Команды работают только от имени владельца подключённого аккаунта — если их
напишет сам собеседник, бот их проигнорирует.

## Премиум (Telegram Stars)

В личном чате с ботом (не в business-чате) доступна команда `/premium` —
бот выставляет счёт в Telegram Stars (100⭐/мес по умолчанию). После оплаты
на месяц снимаются:

- водяная подпись `@<бот> - Диалоги это просто.` под пересланными
  сообщениями/фото;
- лимит `.spam` повышается со 100 до 500 сообщений.

Без премиума подпись добавляется ко всем уведомлениям об удалении/правке/
одноразовых фото.

Выдать премиум бесплатно может админ (по умолчанию ID `7563505180`,
`@Empeeerator`) командой в личном чате с ботом:

```
/give premium <telegram_id> <дней>
```

Список админов настраивается через `ADMIN_USER_IDS` в `.env` (через запятую).

## Как это работает

Telegram Bot API не присылает ботам полное содержимое удалённых сообщений —
только список ID. Поэтому бот сохраняет у себя (в SQLite) все сообщения,
которые видит через business-подключение, а когда прилетает событие удаления —
достаёт сохранённое содержимое и пересылает вам. Отсюда и правило: бот видит
только то, что произошло **после** подключения и пока он был запущен.

## Установка

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Установите зависимости:
   ```bash
   cd bed_dialog_bot
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
3. Скопируйте `.env.example` в `.env` и впишите токен:
   ```bash
   cp .env.example .env
   ```
4. Запустите бота:
   ```bash
   cd ..
   python -m bed_dialog_bot
   ```

## Хостинг (Railway / Render)

Бот работает через long polling — ему не нужен публичный URL/порт, только
машина, которая запускает процесс `python -m bed_dialog_bot` постоянно. Для
обеих площадок нужны одни и те же настройки:

- **Build Command:** `pip install -r bed_dialog_bot/requirements.txt`
- **Start Command:** `python -m bed_dialog_bot`
- **Переменные окружения** (Environment/Variables, вписывать вручную в
  дашборде — не в репозиторий!): `BOT_TOKEN`, `ADMIN_USER_IDS`, при желании
  `DB_PATH`, `PREMIUM_STARS_PRICE`, `PREMIUM_DURATION_DAYS`, `FREE_SPAM_MAX`,
  `PREMIUM_SPAM_MAX`.

### Railway

1. New Project → Deploy from GitHub repo → выбрать этот репозиторий и ветку.
2. В настройках сервиса указать Build/Start Command как выше.
3. Во вкладке Variables добавить `BOT_TOKEN` и остальные переменные.
4. Подключить Volume и указать `DB_PATH=/data/bed_dialog.db` — иначе база
   (сохранённые сообщения, баны, премиум-статусы) слетит при каждом
   передеплое.

### Render

1. New → **Background Worker** (не Web Service — воркеру не нужен открытый
   порт, а веб-сервисы на бесплатном тарифе засыпают и не ловят polling-
   обновления).
2. Подключить репозиторий/ветку, указать Build/Start Command как выше.
3. Environment → добавить `BOT_TOKEN` и остальные переменные.
4. Добавить Disk (persistent storage), смонтировать, например, в `/data`,
   и указать `DB_PATH=/data/bed_dialog.db`.
5. У Render бесплатный тариф обычно доступен только для Web Service —
   Background Worker может требовать платный план; уточните это в текущих
   тарифах Render перед деплоем.

## Подключение к вашему аккаунту

1. В Telegram: **Настройки → Автоматизация чатов** (Business → Chatbots).
2. Укажите username вашего бота.
3. **Важно:** включите права бота на чтение сообщений ("Просматривать
   сообщения" / read messages) — без этого бот не получит ни новые сообщения,
   ни события удаления/редактирования.
4. После подключения напишите что-нибудь в любой личный чат — бот начнёт
   сохранять сообщения этого чата. Удалите или измените сообщение — уведомление
   придёт в чат с самим ботом.

## Ограничения

- История чатов до момента подключения бота недоступна — Telegram её не
  передаёт.
- Одноразовые фото сохраняются, только если на них ответили сообщением, пока
  бот был запущен (так их содержимое становится видно боту).
- Функция "Автоматизация чатов" доступна только с Telegram Premium /
  Business-аккаунтом — это ограничение самого Telegram.
